# Oceanseo 界面质量与内测准备度

日期：2026-10-05（本地）；部分测试文件时间为次日 UTC。此报告针对本轮源代码与独立验收包，不代表公网下载已更新。

## 结论

主要排版、文字和触控问题已修复，应用保持 React / Vite / Tauri，不换框架。方向是「海玻璃导航 + 不透明阅读面」：品牌体现在窗口与导航，任务、聊天、食谱、表单优先保证清晰和稳定。没有复制外部组件模板。

目前具备小规模、受邀、明确接受自备 AI 服务的试用基础；**尚未达到面向普通非技术用户的常规内测交付门槛**。不能用网页布局通过、服务器空闲或模拟 AI 成功来替代真实模型、升级、同步可靠性和长期使用验收。

## 已完成的修正

- 960px 桌面任务列不再横向撑出工作区；长标题、笔记和计数保留可读布局。
- 食谱菜名统一清晰的中文无衬线 18px；采购正文及操作标签维持 14–16px；辅助信息至少 12px。
- 顶栏高度与账号按钮一致，任务笔记入口更易操作。移动端核心按钮按 44px 目标调整，日历在平板和横屏也使用可触控日期与日程点，详细内容在日程列表中查看。
- 取消大量任务卡片的入场位移，避免阅读时文字移动；不使用正文模糊或渐隐。
- 倒计时编辑器补齐初始焦点、焦点圈定、Escape 关闭和返回入口焦点；嵌套日期选择器保持独立关闭顺序。
- 为按需加载页面提供稳定加载态与错误边界：页面资源失败不会使整个应用白屏，可以切换页面或重新加载，不清空已保存数据。
- 按需加载拼豆、主机、工作观察、人物、训练、旅行、食谱和采购；日历按数据变化建立日期索引，不再逐日期扫描整个集合。
- 账号内补充可折叠的数据隐私说明。设置仍不混入登录表单，高级服务与同步诊断默认隐藏。
- 更新隐私文档和下载页源代码，区分旧公开包的个人手动同步与新邀请账号的前台自动同步。静态下载页和隐私页已于 2026-10-06 增量部署，公开安装包保持不变。

主要文件：`src/design-system.css`、`src/App.tsx`、`src/useLayerMotion.ts`、`src/PageLoadBoundary.tsx`、`src/CountdownView.tsx`、`src/CalendarView.tsx`、`src/calendarEvents.ts`、`src/goals/GoalOverlay.tsx`、`src/AccountSettings.tsx`、`src/account.css`。

## 服务器基础设施核对

本轮没有部署新服务、更改账号/生产数据库、修改账号路由或发邀请码；已通过既有发布脚本增量部署静态下载页与隐私页，未替换公开安装包。

- `oceanseo-accounts`、每日备份 timer、个人同步、资源采集及 Caddy 五项均 active；账号服务重启次数为 0。
- 2 核 / 总内存 3915MiB，观察时可用 3320MiB，系统已用约 595MiB；账号服务空闲驻留约 11.1MiB。
- 磁盘 38GiB，已用 2.6GiB（7%）；未设置 swap。
- 业务端口 4789/4790/4791 仅回环；SSH 2222、HTTP/HTTPS 对公网提供。
- `/v2` 邀请账号独立于 `/v1` 私人资料库，已有本机在线 SQLite 备份和每日 timer。观察时 timer 的 `LAST` 为 `-`，首次计划运行尚未得到本轮验证；之前人工备份成功不代表计划任务或异地容灾已完成。

配置可用于开始小规模可信邀请试用，尚无并发用户容量结论。没有做生产压力写入或消耗 AI 额度。公网 `/health` 的静态成功不是账号数据库健康或真实用户登录/同步可用证明。

## 距离常规内测的发布门槛

P0 是推广给普通内测者前必须闭合；P1 可在明确边界的少量邀请试用期间推进。不能把历史功能列表或构建成功当成上线验收。

| 级别 | 差距 | 验收条件 |
| --- | --- | --- |
| P0 发行 | 日常版、验收版、预留正式包及调试签名仍分离；公网没有新账号客户端 | 确认长期包名和签名所有权、离线备份密钥；连续两个版本安装升级保留资料；旧包迁移路径和备份明确；发布带散列、版本说明的真实候选包 |
| P0 核心体验 | 普通用户仍需自备兼容 AI 服务；隐藏高级配置并没有提供官方 AI 能力 | 选择托管 AI 或明确仅邀请 BYOK 技术用户；若托管则补账号鉴权、额度、限流、费用预算和数据告知；真实模型跑通想法 → 引导 → 确认行动，不用模拟回复代替 |
| P0 数据可靠性 | 前台自动同步已具备基础，但完整断网/冲突/撤销/重试组合及长期运行未闭合 | 两台真实设备覆盖断网编辑、并发修改/删除、旧设备回连、token 到期/撤销、重启、未发送草稿和通知资料库切换；无丢失、跨账号泄漏或重复执行；普通流程无需手动同步 |
| P0 运维 | 备份仅同机，首个日定时备份缺观察证据；没有外部告警闭环 | 验证定时任务实际执行；加密异地副本、留存期、一次恢复演练；API/数据库级健康与外部告警；制定恢复目标，而非仅验证静态首页可访问 |
| P0 反馈/隐私 | 发行主体、固定支持入口、账号删除与恢复流程及备份留存政策不完整 | 内测者能联系维护者、申请删除/恢复；明确范围和响应方式；隐私页面与实际候选版/部署同步。小范围可人工办理，但必须有可执行流程 |
| P1 性能 | 桌面预热合成数据已接近/达到 250ms 目标，移动端大数据量和冷启动仍未知 | 继续按需/虚拟化优化；完成手机大数据量、首屏冷启动、低内存恢复及电池测试；保留搜索与键盘可达性 |
| P1 同步范围 | 生活模块、通知配置、密钥、草稿不参与账号同步 | 持续清楚提示当前范围；先定义人物/旅行/采购等的合并、删除与隐私规则，再扩展，禁止直接同步整个配置目录 |

建议顺序：先定发行和 AI 内测模式，闭合同步/备份/支持门槛，再发少量邀请；随后处理大列表与多厂商覆盖。暂不新增更多生活模块，不将“UI 优化”扩展为新云服务或下游项目开发。
