# 想法与目标 · 0.11.0

本文记录 0.11.0 的分栏整理台。**0.12.0 已统一为对话主界面、只读理解图和右侧交付清单**，操作方式见 [当前使用说明](conversation-workflow.md)。底层目标、任务、依赖和历史数据继续使用。

## 从一团乱麻到下一步

全局导航进入「想法与目标」。直接写下工作、生活、担忧、期限或时间限制，点击「存入收集箱」，或者点击「请小汐梳理」先保存原文再生成方案。聊天中的「把这些想法带到目标整理台」可交接当前输入或最近一条用户消息；小汐也可以提出整理台操作卡，卡片可展开检查交接内容。

收集箱独立于聊天记录，不随聊天的 40 条消息上限滚动丢失。可以把想法先放一放，日后再放回收集箱。未经存入的编辑文本也在本机暂存，切换页面可继续。

小汐对照原有目标、行动及任务，提出目标、子目标、完成标准、前置行动、预计时长和执行入口。必要时最多提出三个澄清问题：把回答补充到收集箱后再次整理，下一次请求包含上一份草案的问题。未明确的日期可以留空，暂缓建议不会变成待办。

方案可以手动修改或从「手动建一个目标」开始，未配置 AI 时也能使用。已有任务通过稳定 ID 关联；采用方案不覆盖已有任务的记事本、日期或完成状态。需要修改任务正文时从既有任务编辑器操作。已采用目标也可以从「编辑目标与行动关系」继续调整。

点击「采用整份方案」后，任务和目标关系在同一个 SQLite 事务里提交。真实回执返回之后才显示已保存。暂缓建议进入「以后再说」的收集记录；原文保留。原始想法已暂缓、目标关系变化、关联任务已编辑或删除时，旧方案会被拒绝，应重新整理。

## 现在先做什么

首页和目标页的「现在先做」从已采用的行动中推荐下一步：

- 排除已完成、目标或上级目标已暂停/结束、尚未开始、主动暂缓、存在阻碍及前置行动未完成的项。
- 按当前可用时间、精力与推荐数量限制筛选；一组建议的预计总时长不超过可用时间。
- 优先考虑到期/逾期、重要事项以及能解锁后续行动的事项，随后比较截止日期与时长。排序由本机规则计算，可以检查和修改条件。
- 可展开查看等待与暂缓的原因。目标的检查日期到期时会提示清点。

「可用时间」表示此刻这一组建议可使用的时间，不是工时追踪器；完成工作后可根据实际剩余时间调整。应用不自动把截止日期变成占满一天的安排，也不预订时段。

目标是否完成由用户对照完成标准判断。行动完成比例只显示活动记录，不等同于成果验收。

## 在哪里做

每个行动可以选择事项记事本、训练、旅行、采购、食谱、工作观察或拼豆。

- 事项入口打开对应记事本。
- 训练、旅行可选择具体计划和日期；没有关联对象时，以稳定行动 ID、标题/说明及明确条件初始化独立草稿，既有其他草稿保留。训练可携带项目、组数、次数与周期；旅行可携带起点、目的地、预算、目的、交通与住宿偏好。保存后回连目标行动。
- 采购入口可以定位已有物品；新流程预填名称、数量和分类，仍由用户检查后添加。食谱可携带人数、每周预算、饮食偏好、过敏信息与健康目标，继续使用原业务逻辑。未明确的条件留空，不由整理器虚构；采用前可查看提取的条件，进入业务表单后继续编辑。
- 工作观察定位选定项目；同步仍在原页面审核。拼豆进入现有唯一图纸工作台并显示行动说明。
- 页面上显示来源目标和行动说明，可直接打开记事本、明确标记此步完成或返回目标。普通导航离开后结束本次交接。

已完成的任务、匹配计划与日期的实际训练记录，以及已勾选的关联采购物品，都可以作为行动完成证据并解锁后续行动。保存旅行方案、生成食谱或产生 Git 提交，不自动等同于完成目标。

## 复盘与自动化

「复盘与节奏」保存实际进展补充、晨间安排、晚间清点和 AI 复盘。建议和用户决定保留，可把复盘内容带回整理台生成调整方案；AI 复盘不直接改写任务。

晨晚本机清点可随偏好设置的每日提醒时间执行，每周本机清点的星期和时间可独立配置。只在应用运行或恢复焦点时检查，最多补两小时内错过的时段，按本地日期和清点类型去重。每日系统通知可以附带符合条件的下一步。需要保持应用或托盘进程运行并允许系统通知。

自动化范围是本机清点和提醒；付费 AI 整理/复盘由点击触发，方案采用由用户确认，GWorkspace 同步沿用已有审核。这些设置在整理台内可见。没有后台付费轮询或自动修改你的目标优先级。

## 保存、恢复和撤销

目标、关系、收集箱、方案、复盘及设置保存于 `tideplan.goals.v1`，与原任务共用本机数据库并纳入 JSON 备份。原任务 `1.0.0` 数据格式未改动，没有修改生态契约。

保存请求带有版本及操作编号。本机待写请求 `tideplan.goals.pending.v1` 在收到回执前保留；重试同一请求不会重复创建任务。发生冲突时，可保留恢复副本并重读数据库，恢复副本位于应用 WebKit 存储的 `tideplan.goals.recovery.*`，供人工排查，不自动重放。备份会等待目标写入；有未确认的写入时阻止导出或恢复，避免遗漏。恢复期间阻止新的目标写入。

最近一次采用可以撤销，前提是目标关系没有继续修改，且本次创建的任务没有被编辑、完成或删除。撤销只移除本次未改动的新任务并恢复之前的目标关系和收集状态，保留此前已有任务；修改过的用户工作不会被整批删除。后续操作使整批撤销失效时，应逐项调整。

编辑中的收集输入、复盘补充及训练/旅行草稿只暂存本机，不属于已提交的 JSON 备份；需要备份原文时先存入收集箱或保存复盘。原文、方案和复盘可能含私人信息，备份应私密保管。

## AI 数据范围及边界

整理前可以展开本次摘要。默认发送收集箱原文、目标及行动关系、至多 300 项任务摘要、至多 200 个业务对象名称/ID、最近五次复盘的明确补充和检查时间。任务记事本必须勾选才发送；人物档案、生日、项目源码/路径、API 密钥不作为上下文发送。上下文截断会明确标记。聊天中分享任务摘要也包含有上限的目标关系摘要。

复用现有 API_KEY、BASE_URL 和模型。结构化方案遵循 [OpenAI Structured Outputs 文档](https://developers.openai.com/api/docs/guides/structured-outputs)，聊天交接使用既有工具循环。请求 `store:false`，单次超时 120 秒，HTTP 响应最多 1 MB；第三方留存和费用仍按服务商政策。取消等待会忽略迟到结果，不能撤回已发送到服务商的请求。

目标整理不是语义理解准确性的保证。验收使用本地模拟服务与隔离浏览器；实际模型对复杂输入的质量、兼容服务权限及原生跨系统体验需要用实际配置继续验证。
