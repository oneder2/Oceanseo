# 照片提炼与交界净化 · 0.13.0

入口：个人项目 → 拼豆图纸 → 导入。沿用 React/Tauri 与拼豆工坊的大画布，AI 流程放在可收起的导入面板中；海青、浅色纸面和原图/结果对比保持现有风格，没有引入外部组件模板。

## 从照片制作图纸

1. 选择 PNG、JPEG、WebP 或 BMP 图片，本机输入限制为 16 MB / 1600 万像素。
2. 选择「AI 提炼主体」，点击「识别图片主体」。识别结果包含可见主体、辨识特征和构图建议，可以直接修改，也可以跳过识别自行填写。
3. 选择平涂、像素或贴纸风格；背景可选纯色突出主体或保留主要景物。补充应保留/去除的内容，按目标网格与颜色数量生成插画。
4. 点击生成图查看原图对比，或保存插画 PNG。勾选「使用这张插画生成图纸」后，调整下方网格、品牌与颜色数，生成最终拼豆预览。
5. 预览满意后「应用图纸」。原图纸不会在识别、生成或预览阶段被修改；应用后可整体撤销。

本机转图不调用 AI。AI 图像只是设计中间结果：最终网格、色号和用豆数量由本机转换算法及品牌色卡计算，不能把模型画出的颜色理解为厂家实物色号。白色背景仍是图片中的颜色，不自动视为透明区域。

原图、生成插画和主体说明只保留在当前拼豆页面内存中，离开前可保存插画；正式应用的拼豆图纸继续自动保存并纳入备份。图片模型名称作为本机草稿保存，不含密钥。重新生成失败保留上一次结果；停止等待后迟到响应不采用，服务端请求仍可能继续计费，不自动重试。

## 服务配置

继续共用偏好设置中的 API_KEY、BASE_URL 和主模型，无需另填密钥。主模型需要支持图片输入、结构化输出及 Responses 的 `image_generation` 工具。普通文本聊天可用不代表图片工具也可用。

「图片模型与服务」中可填写图片生成模型名称，默认 `gpt-image-2.5-flare`，可改为服务商提供的兼容模型。请求固定为一张中等质量 PNG，依目标比例选择 1024×1024、1536×1024 或 1024×1536；这些是插画分辨率，最终豆格仍为用户设置的 1–160 格。接口不兼容、权限不足、限流、未完成响应或无图片结果会明确报错，原图和图纸不变。

API 依据：[OpenAI 图片生成文档](https://developers.openai.com/api/docs/guides/image-generation)。使用 Responses 图片输入与图片生成工具，不接收任意模型返回的网址进行下载。请求共用配置，仅发送当前图片与设计说明，不附带人物档案、任务、其他聊天或本地文件路径。

上传前在本机把原图缩至最长边 1024 px 并重新编码 PNG，去掉原文件 EXIF 等元数据；图像内容本身仍会发送到配置的服务。请求设置 `store:false`，服务商日志和留存仍依其政策。密钥留在 Rust 后端。响应限制大小并检查 PNG 头部与像素上限，前端再次解码；不是完整图片安全扫描。

## 交界杂色修正

原问题有两层：面积缩图把交界两侧混合成新颜色；量化后的保边规则又保护了这些细长过渡线。单纯增加多数投票强度，会破坏眼睛、高光和轮廓。

现在增加以下处理：

- **平涂源图判别与边缘采样**：有足够纯色覆盖时，交界采用空间上有支持的实际色簇，避免发明中间色。重复高频纹理缺少空间分离证据时仍平均。连续色调照片保持面积采样，避免把真实细纹过分锐化。
- **最终豆色后的区域净化**：以四连通色块和实心邻域识别没有内部面积的薄色带；检验它是否为相邻两色或三色的 RGB 混合，处理长交界线和三色汇合点。较强模式也处理小簇偏色。
- **细节与连通保护**：透明格不参与填色，不引入新色；有实心内部的区域、明显的亮度极值保留。只采用整块都可解释的替换，并合并进直接相邻的稳定色块，避免把一条细线改碎成更多孤点。

照片转换默认「较强」并启用「交界净化」。可关闭净化作对照；关闭去杂色或使用像素原稿时不运行新净化层。已有图纸不自动改写，需要重新导入原图或 AI 插画以生成新预览。

对于合成的已知交界，测试要求混色残留为零；任意照片的所有小色块是否属于杂色无法仅凭局部算法判断。孤立点也可能是眼睛、星光或装饰，不能用删除所有小点来保证图像正确。复杂人物照片建议先提炼成插画，再检查拼豆预览。
