# 主机与服务

入口：个人项目 → 主机与服务。桌面和 Android 共用档案；浏览器支持本地预览，不进行原生网络检查或 AI 调用。

## 日常使用

添加主机，填写名称、用途、项目及供应商。其余分为档案、服务、费用与期限、维护、监测五页签，可跨页签编辑，最后点击“保存档案”。退出未保存内容会提示。规格的 0 表示尚未记录，不代表供应商提供零资源。

每台主机下可保存多个服务，关联已有项目名称或自定义名称，记录地址、端口、目录和数据库。项目名称在本模块中作为关联标签，不会创建 GWorkspace 项目或触发工作观察同步。域名作为服务访问地址记录，并通过“重要期限”添加域名到期事项。

续费价和每期税费用于月均成本，首期价格单独保存。USD/CNY 等原币分别汇总，不自动换汇。“自动续费”仅记录供应商设置，不改变供应商账户。点击“记录本期已付款”并确认后，保存一笔实付记录、推进一个账期。每月固定 31 日的账单在二月落到月底，下月恢复 31 日；若实际供应商不同，可修改固定账单日或下次续费日。实际折扣、税费以付款前核实的数值为准。

续费与未完成期限自动显示在计划日历和总览近期提醒，点日历事件打开主机。退款截止、取消续费截止、证书、域名等由用户录入，不猜测订单日期；勾选已处理或归档主机后隐藏。提醒天数可按主机配置。桌面每日通知会带主机待处理数量；Android 保持现有系统每日通用提醒（并非新增逐主机定时闹钟），打开应用后查看具体到期内容。

“加入任务”只打开带来源的任务草稿，需要在编辑器保存。同一来源已有任务时打开已有任务，不重复创建；任务完成不会自动标记已经付款或修好服务器。主机期限变动后已有任务日期不会擅自修改，需核对。删除/归档主机不删除已有任务。

备份、恢复验证日期和账期已用流量是人工核实记录。可在维护页填写位置、周期、保留策略和日志；无成功备份记录或超过设置间隔时提示检查。采集网络计数不能代替供应商账单用量。

## 监测与采集器

服务检查：填写最终 HTTPS 健康端点，保存后点击立即检查。2xx 视为这一个端点可达，其他状态或网络失败显示异常。客户端不跟随重定向、不接受 URL 里的用户名/密码/查询参数/片段，不显示响应正文。HTTP 只允许本机 loopback 开发测试。

资源采集器：`services/host-monitor/collector.py`，Python 3 标准库，在 Linux 上只读 `/proc` 和指定磁盘统计，返回 CPU、内存、磁盘使用率、系统运行时间、启动后网卡收发计数。默认磁盘为 `/`；其他挂载点用环境变量指定。多网卡/容器虚拟网卡可能重复统计流量，不能用于费用结算。短 CPU 样本不表示持续负载。采集端缓存 10 秒减轻开销。

2026-10-04 已在自有 VPS 部署采集器，公网端点为 `https://oceanseo.gellaronline.cc/metrics`，见 [部署与接入报告](server-deployment-2026-10-04.md)。以下步骤用于其他服务器；现有实例与同步服务共享域名，但使用独立令牌：

1. 将采集器放到 `/opt/tideplan-monitor/collector.py`，代码普通用户可读、不可写。安装 Python 3。
2. 在服务器本地生成独立随机令牌，如 `python3 -c 'import secrets; print(secrets.token_urlsafe(32))'`，保存到仓库外、权限 600 的 `/etc/tideplan-monitor.env`：

   ```text
   TIDEPLAN_MONITOR_TOKEN=替换为随机值
   TIDEPLAN_MONITOR_PORT=4790
   TIDEPLAN_MONITOR_DISK=/
   ```

3. 安装 `tideplan-monitor.service` 到 systemd 并启动。动态非特权用户运行；采集服务只绑定 127.0.0.1。
4. 参考 `Caddyfile.example` 用独立域名/HTTPS 反向代理 `/metrics` 到 127.0.0.1:4790。不要把采集器端口直接暴露公网；公网网关按需添加速率/连接限制。此标准库服务面向个人轻量部署，不宣称公开高并发能力。
5. 主机监测页填写 `https://metrics.你的域名/metrics` 并保存档案；填写独立采集令牌，点击“保存采集令牌”，再检查。令牌与完整采集地址绑定，改地址必须重新保存，不随重定向发送。

前台检查间隔为 0 时关闭自动检查，启用后至少 5 分钟。仅应用运行且页面可见时检查；Android 后台不持续检查。展示检查来源、检查时间、采样时间，超过 `max(15 分钟, 2 × 检查间隔)` 或采样时钟明显在未来则标为过期。可调整 CPU/内存/磁盘阈值。每台保存最近 120 条样本，可在详情查看，不从稀疏数据推断全天 uptime。

## AI 与数据边界

“AI 与周摘要”先显示本地概况和将发送的脱敏摘要，用户勾选后才调用共享 AI 配置。未配置时可打开设置；无独立 AI 密钥。摘要仅含名称、用途、项目、费用、日期和数值样本，不含地址、凭据引用、订单号、目录、维护日志。名称和用途仍是用户文本，请勿放入秘密。模型输出需引用真实主机，建议仅打开待保存任务。

订单识别支持文本及 5 MB 内的 PNG/JPEG/WebP。发送前自行遮盖账户/支付信息；所选文本和图片会发送到配置的 AI 服务。模型需支持 Responses 结构化输出，截图还需支持图像输入。输出是草稿，未知或矛盾参数保留待核实说明，不确定的续费价不假定为促销价；不会保存订单图片。图像输入依据 [OpenAI 官方图像文档](https://developers.openai.com/api/docs/guides/images-vision)。不同兼容提供商支持程度不同，识别准确性必须人工检查。

现有对话助手新增可选“主机运行摘要”读取范围，默认不勾选。助手只解释、建议和打开页面/草稿，不远程执行命令、付费、重装或修改服务。周摘要由用户主动生成并可保存最近 30 份，不自动发起定时付费 AI 请求。

SQLite 保存档案并加入完整 JSON 备份及恢复校验；最多 100 台主机，每台 100 服务/期限、300 日志/付款记录，总文档上限 2 MB。采集令牌单独保存在本机 `host-credentials.json`，Android Keystore 加密，桌面文件权限 600，不进入业务备份、核心同步或 AI。不要在普通档案填 SSH 密码/私钥，使用密码库条目名作为凭据引用。主机档案暂不参与核心跨设备同步，可通过完整备份迁移。

## 验证入口

- `npm test`：账期、归档、成本、日期、陈旧样本、数据校验、AI 摘要隐私。
- `cd src-tauri && cargo test --lib`：数据库备份/恢复、端点安全、原生 HTTP 与 AI 协议。
- `cd services/host-monitor && python3 -m unittest -v test_collector`：Linux 采样和真实 HTTP 鉴权。
- `scripts/infrastructure-smoke.js`：独立浏览器建档、日历、任务、防重复、付款、未保存拦截和移动宽度。
