# 0.11.0 验收报告

日期：2026-09-20。范围：从混乱想法到目标、子目标、实际行动及复盘。没有修改 ecosystem contracts 或启动下游项目任务。

## 原有基础与本次补齐

原有应用已经具备 SQLite 任务与记事本、计划日历、人物资料、训练/旅行/食谱生成、采购清单、项目观察、共享 AI 配置，以及小汐的摘要读取、页面导航和待办草稿工具。缺少的是跨模块的持续目标关系、依赖排序、想法来源、执行交接及复盘循环。

本次增加全局「想法与目标」整理台，将这些基础串联起来：

- 收集原始想法并保留来源、暂缓记录和未提交输入。聊天内容可明确交接到整理台。
- AI 对照已有任务提出目标、子目标、完成标准、依赖及行动，缺失信息最多提出三个问题。可手动建立或编辑方案，未配置 AI 也可使用。
- 一次采用生成任务与关联关系；原有任务的正文、笔记及日期不被覆盖。事务提交、版本冲突检查、幂等重试与安全撤销保护用户已有工作。
- 首页「现在先做」结合日期、依赖、暂停、时间及精力，推荐少量可执行行动，解释等待原因；行动全部完成时提示检查目标成果。
- 行动进入对应记事本、具体训练/旅行/采购/项目，或带入明确条件的新建流程。训练组数与周期、旅行起终点与预算、采购数量与分类、食谱人数与预算等均有受限结构及校验。
- 训练实际完成和采购勾选可以作为行动完成证据；保存方案或 Git 活动不等于达成目标。提供本机晨晚/周期清点、用户补充及按需 AI 复盘。
- 新数据纳入备份恢复；保存状态包含目标操作，失败请求保留到取得回执；载入失败显示重试入口。

沿用 React/Tauri 与原有半透明界面。整理台采用暖白纸面、海青关系线和突出单项行动的布局；收集、执行、复盘分成三个页签，窄窗口为单列。详见 [使用说明](goal-workflow.md) 与 [实施验收清单](goal-workflow-plan.md)。

## 验证记录

- 前端测试 55 项通过，覆盖目标结构、循环依赖、旧任务复用、过期方案、容量与精力、暂停、真实业务完成证据、隐私投影、定时清点去重及条件边界；既有业务测试保持通过。
- Rust 测试 43 项通过，覆盖 SQLite 原子性、失败回滚、重复提交、重启/备份恢复、安全撤销和本地模拟 AI 请求。
- `cargo clippy --all-targets -- -D warnings` 通过。
- TypeScript 与 Vite 生产构建通过。主入口压缩后约 506 kB，仍有非阻断的分包体积提示；整理台与地图已按需加载。
- 隔离 Chromium 验收：收集原文、手工方案、依赖设置、采用、撤销、前置完成解锁、进入训练、复盘重载及 620×560 窄窗口通过，无页面运行异常。
- 另外使用明确的本地测试数据验证训练组数/次数/周期、旅行地点/预算、采购数量与完成回连、食谱人数/预算/忌口的交接。不是实际模型生成质量测试。
- 最终补充浏览器检查：所有行动已完成时显示成果检查提示；损坏目标数据会显示错误和重读入口，恢复有效数据后可继续工作，顶栏错误状态同步清除。
- 可复现脚本：`scripts/goals-smoke.js`、`scripts/goal-handoff-smoke.js`。截图：`output/playwright/goals-plan.png`、`goals-next-action.png`、`goals-narrow.png`、`goal-training-handoff.png`、`goal-meals-handoff.png`。
