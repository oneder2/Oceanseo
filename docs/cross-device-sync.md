## 范围与使用

设置 → 跨设备同步，填写你部署的 HTTPS 地址与独立访问令牌 → 保存配置 → 检查更改 → 处理冲突 → 确认同步。另一台设备填同一地址与令牌，执行相同步骤。AI 密钥不是同步令牌。

当前同步任务、事项笔记、日期、完成状态，以及整组目标、已保存对话、理解图、交付清单与执行回执。日历由同步后的任务日期直接显示。尚未同步人物、饮食、采购、训练、旅行、倒计时、助手形象配置、拼豆和工作观察。密钥、通知时间、编辑草稿、设备凭据不上传。只同步数据库中已保存的记录。

此版本是**手动检查与确认同步**。离线时继续本机使用，网络恢复后主动检查；没有后台轮询、自动上传或推送。应用网络中断／服务端不可达不会删除本机数据。成功后统一重新载入页面，保留本机编辑草稿。

每个服务实例／令牌对应**同一个人的资料库**，多台设备共用。不能把一个令牌发给不同内测用户，否则他们会读写同一份资料。多用户账号、邀请与设备级撤销尚未实现；其他用户应使用独立服务实例／数据库／令牌。不要把本服务直接当作公开注册平台。

## 合并规则

- 每台设备持久化上次成功同步的共同基线。当前数据库与基线比较得到待上传修改；不依赖设备时钟判断谁胜出。
- 新增使用原有稳定任务 ID；两台设备修改不同任务自动合并。同一任务的互不重叠字段可合并，例如电脑改标题、手机改笔记。
- 同一字段同时修改、删除与编辑冲突需要用户选择本机或服务端版本。不会按“最后时间”静默覆盖。
- 目标与对话包含交付执行和撤销关系，作为一个整体比较。两端都修改时展示两份内容供选择，不自动拼接行动记录。执行日志、目标修订号和撤销上下文属于本机，导入时重新建立；已保存的跨设备执行回执保留。
- 删除使用持久 null 墓碑，内测阶段不自动清理。旧设备不会因为离线后重新加入就把已删除事项复活；同 ID 的旧记录首次连接遇到墓碑时需要解决冲突。
- 服务端以数据库事务比较 revision，仅接受在最新基线上提交的完整合并结果。过期请求返回 409，重新检查后再提交。两端并发提交只有一个成功。
- 上传成功但响应丢失时，重新读取后核对内容；重复重试不会生成新任务 ID。若期间本机又改了相同记录，会保留本机并重新展示冲突。
- 应用前后检查本机快照，期间若有新保存则拒绝覆盖。业务数据与共同基线在同一 SQLite 事务提交。
- 校验服务端协议、资料库标识、版本回退、历史 ID 和全部业务记录。遇到资料库更换或回滚会停止，不能简单把服务器重建成空库后强迫旧客户端上传。

## 备份与恢复

提交前在本机 `migration-backups/before-sync-*.json` 写入完整本机备份及两端同步版本，写入失败则停止提交。设置页可导出最近一次成功同步前的安全副本；该文件可通过“选择备份”恢复其中的本机备份，双方原始版本也留在 JSON 中供维护者恢复。旧副本不自动清理。

恢复旧备份后的修改和删除会在下次确认同步时传播；先检查更改再确认。断开连接只清除本机同步地址与令牌，保留数据和共同基线，以便之后连接原资料库。JSON 业务备份不包含同步令牌或基线，迁移到全新安装时作为新设备合并，可能需要处理冲突。

服务端 SQLite 需要单独备份，使用 `services/sync/backup.py` 的在线 backup API，不直接复制运行中的 SQLite 主文件。服务器备份恢复若降低 revision，已同步过的客户端会阻止回退，需维护者协调恢复流程，不能擅自清空客户端基线。

## 服务与安全边界

仅使用 Python 3 标准库、SQLite 和现有客户端 HTTP 库。服务默认监听 127.0.0.1，经 HTTPS 反向代理访问；客户端拒绝明文局域网／公网 HTTP、URL 中的密码及重定向。只有 literal loopback 与 localhost 允许本机 HTTP 测试；Android 可通过 `adb reverse tcp:4789 tcp:4789` 验证。

访问令牌至少 32 字符，部署时使用高熵随机值。Android 用 Keystore 加密本机配置；Linux 配置权限为 600，不包含在导出的业务备份中。更换令牌须更新所有设备；旧令牌立即失效。

数据传输使用 HTTPS，但**没有端到端加密**：服务器管理员可读取资料库和备份。本机安全副本也包含完整私人资料，须私人保管。服务不记录请求正文或 Authorization；未接入第三方遥测。请求上限约 16 MiB，最多 10000 个有效任务／50000 个含墓碑记录。当前协议传输完整同步快照，尚未做分页增量、大附件同步或容量压测。

## 服务器选型与部署

个人到数十人独立内测实例可先考虑 2 核、2 GB、40 GB SSD；推荐 2 核、4 GB、40–80 GB SSD，普通 5 Mbps 网络起步。此为文字／结构化数据同步的工程估算，尚非并发容量保证。没有 GPU 需求，不在服务器运行 AI 模型。逐用户独立实例会增加运维成本；扩大用户数前改为正式多租户服务并压测。

建议 Ubuntu 24.04 LTS 或 Debian 12、稳定 HTTPS 域名和服务器外的私有备份。机房按真实用户网络可达性选择；国内部署的备案、后续分发和服务要求需按实际模式核实。

以下为部署其他私有实例的基础步骤；本项目已部署的实例及文件位置以 [部署报告](server-deployment-2026-10-04.md) 为准：

1. 建立无登录权限的专用系统用户 `tideplan-sync`，代码放 `/opt/tideplan-sync`，私有数据目录 `/var/lib/tideplan-sync` 归该用户所有，权限 700。
2. 将 `server.py`、`backup.py` 放入代码目录；将 `sync.env.example` 复制到仓库外 `/etc/tideplan-sync.env`，替换随机令牌与路径，文件权限 600。可在服务器本机用 `python3 -c 'import secrets; print(secrets.token_urlsafe(32))'` 生成令牌，妥善保管，不贴入公开日志。
3. 安装仓库提供的 `tideplan-sync.service`，通过 systemd 启动；只让反向代理访问 127.0.0.1:4789。
4. 参考 `Caddyfile.example` 配置真实域名、HTTPS 和请求大小限制。防火墙只开放必要的 SSH、80、443。公网入口需额外配置速率／连接限制，Python 内置服务器仅作为代理后的私有内测服务。
5. 两台设备配置同一服务并测试新增、修改、删除、离线冲突与令牌撤销。确认备份可读、可恢复后再承载日常资料。
6. 每日运行 `python3 backup.py /var/lib/tideplan-sync/vault.sqlite3 /独立备份目录/一个新文件.sqlite3`，再复制到服务器外的加密存储；脚本拒绝覆盖已有文件。不要只依赖同一块云盘的副本。

## 本地验证

`cd services/sync && python3 -m unittest -v test_server` 验证鉴权、并发、重试、墓碑和非法请求。Rust `cargo test --lib` 包含临时两数据库与本机真实 HTTP 服务的同步测试，服务与数据都隔离在临时目录，不调用真实 AI 或用户云服务。

正式签名内测、长期密钥备份、远程 CI 实际运行、多设备连续使用、HTTPS 部署、断网与升级矩阵是继续推进的门槛；交付此模块不等于第二阶段已经全部完成。
