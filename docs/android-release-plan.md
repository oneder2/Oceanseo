# Android 与公开发布路线

本路线接续 1.0 可靠性计划。先交付 Android 内测验证包，再推进跨设备使用与公开发布；不修改生态契约，不启动 GWorkspace 下游任务。

## 阶段一：原生能力与核心流程

2026-09-29 用户反馈：第一阶段初步验收未发现问题，同意继续第二阶段。此前自动化记录的真实服务／多厂商／跨日通知覆盖边界仍保留，不能把该反馈扩大为所有场景已验证。

- 复用 React / Rust / SQLite，按平台隔离托盘、自启、窗口控制和工作观察。
- 手机主导航为今天、助手、工具；首期包含任务、笔记、日历、倒计时、人物、训练、饮食采购和旅行。
- 暂不开放手机拼豆工作台及项目目录扫描；关联任务仍保留，不删除备份中的桌面业务数据。
- Android 原生提醒、文件选择、返回键、键盘与安全区域；验证进程重新启动后数据不丢失。
- 产出独立包名、调试签名的 ARM64 APK。阶段报告列明真机和模拟服务验证，不能混同真实 AI 服务验收。

## 阶段二：可持续内测与跨设备方案

0.16.0 开始交付个人自托管同步：任务与笔记按记录／字段比较，目标与已保存对话作为整体处理冲突；离线本机记录保留，手动检查确认后双向合并。2026-10-04 已部署私人后端及下载页，见 [服务器报告](server-deployment-2026-10-04.md)。范围、限制、恢复与部署见 [跨设备同步说明](cross-device-sync.md)。2026-10-05 已完成统一界面、最终 Pixel 核心流程、Linux/Android 隔离双端同步、两平台旧版升级和 0.18.0 公网下载发布，见 [0.18.0 记录](release-0.18.0.md)。首批实现不含生活模块同步、多用户账户或后台自动同步；第二阶段的真实模型、正式资料库连续使用及多厂商覆盖仍待后续验收，不因本轮 UI/UX 交付完成而直接进入商店发布。

0.15.0 本地内测推进：提醒检查及通知／频道／电池设置入口、采购清单系统分享、手机采购可读性与触控优化。验收范围与产物见 [0.15.0 报告](release-0.15.0.md)。以下阶段门槛继续有效，不以这些局部改动代替完整发布验收。

- 扩充不同厂商、Android 9–16、字体放大、横屏与无障碍测试矩阵。
- 验证系统省电、通知权限变化、重启、时区与夏令时、升级／恢复失败；若需要分钟级准时，再设计精确提醒权限流程。
- 对话可取消／恢复、弱网提示、导出与分享、未完成编辑的保存状态持续完善。
- 同步作为单独工程：先确定账户与部署方式、服务地域、费用和数据保护策略；核心记录使用稳定 ID、修订号、删除标记、冲突与离线队列。不能覆盖 SQLite 文件代替同步。
- 本地备份暂用于手动迁移，恢复会覆盖本机，不能称作双向同步。
- 使用实际支持的 AI 和地图服务验证；BYOK 可继续内测。官方 AI 后端需要登录、配额、限流和预算控制，不在 APK 放开发者密钥。

## 阶段三：正式发行

- 确定发行主体、目标渠道（签名 APK / Google Play / 国内市场）、稳定 applicationId、签名归属和密钥备份；核实提交时最新目标 SDK、隐私与渠道要求。
- 准备隐私政策、支持入口、第三方许可／色卡来源、权限说明、商店截图、变更记录与数据删除方法。
- 完成正式签名 APK / AAB、版本号递增、旧资料升级与恢复演练、发布校验和、回滚说明。
- Linux Mint / Ubuntu / Debian 安装升级和桌面功能回归仍是独立门槛。
- 发布动作由实际渠道与账号决定。本地内测成功不等于已完成上架审核。

## 构建与安装

环境：Node 22、Rust stable 与 aarch64-linux-android、JDK 17/21、Android SDK 36、build-tools 36.1、NDK 28.2。配置 JAVA_HOME、ANDROID_HOME、NDK_HOME。

```sh
npm ci
npm run android:doctor
npm run android:build
```

Android 工程已纳入版本控制，包含原生提醒与安全存储。**不要再次运行 `tauri android init` 覆盖工程**。构建输出在 `src-tauri/gen/android/app/build/outputs/apk/`。

调试包 `com.tideplan.mobile.debug` 与正式预留包 `com.tideplan.mobile` 使用独立沙箱。调试包可直接安装，仅供内测，包含 WebView 调试能力；正式包不能直接继承调试包数据，可用应用备份迁移。跨电脑生成的默认调试签名可能不同，覆盖安装需使用同一调试密钥或先导出备份，不能直接删除已有数据。

正式构建命令 `npm run android:release` 要求 TIDEPLAN_KEYSTORE_PATH、TIDEPLAN_KEYSTORE_PASSWORD、TIDEPLAN_KEY_ALIAS、TIDEPLAN_KEY_PASSWORD，缺少时会停止。密钥放仓库外并离线备份；脚本不创建或上传密钥。桌面 applicationId 保持不变，避免改变现有用户数据目录。

`.github/workflows/android.yml` 可手动执行或由相关 PR 触发，仅上传内部调试产物，不上传商店、不使用正式密钥。CI 的临时调试签名不用于连续公开升级。
