# 人物与生活规划基础设施

版本：0.9.0。只修改 Oceanseo，不调用 GWorkspace、不修改生态 contracts。

## 使用顺序

先在全局导航的「人物档案」建立自己及同行者；训练与旅行位于「生活与出行」。AI 沿用偏好设置中的 API_KEY / BASE_URL 和既有 Responses 接口。未配置时可手动管理档案、训练和行程。

旅行地点检索另需「偏好设置 → 旅行地图」中的高德 **Web 服务类型 Key**，不是 JS API Key。地图采用在线 OpenStreetMap 底图，地点搜索和步行/驾车路线来自高德。用户逐站选择查询结果；坐标保存后再规划当天路线。最多一次规划 20 站。没有返回结果的地点不添加坐标，查询失败不绘制假路线。跨城高铁、航班、公交班次及票价需自行核实。

## 人物

`Person` 使用稳定 ID；保存姓名、公历生日、关系、忌口与过敏、喜好、爱好、特长、健康与行动注意、私人备注和归档状态。生日可不填，不能录入未来生日。年龄、属相、星座为派生值，不另存年龄，避免随时间失真。

年龄以当地日期和实际生日比较；2 月 29 日出生者在非闰年按 3 月 1 日递增。属相使用系统 Intl 中国农历年份，以春节为分界；不支持该历法时明确显示无法换算，不按公历元旦猜测。星座采用常见日期区间，不作占星预测。当前不提供农历生日输入或农历生日提醒。

归档不删除人物，也不破坏已保存计划的关联。`profileContext` 只提取选中人物的姓名、年龄、忌口、偏好、爱好、特长和健康注意；不发送生日原文、关系与私人备注。只在主动运行 Agent 时发送这些字段。

## 训练

周期由开始日期、间隔天数、训练次数和项目组成；每个训练日重复此周期的项目模板。间隔 1–90 天，周期 1–104 次，每个计划 1–30 个项目，每项 1–30 组，每组目标 1–1000 次/秒/自定义单位。按日历日推进，跨夏令时不漂移。

Agent 基于输入与执行人画像提出项目和建议，保持用户选定的周期。草稿可编辑，确认后才成为日历事件。已有周期可以复制成新周期；归档从日历隐藏，但保留历史记录。

`Workout` 用计划 ID + 日期对应记录，每组实际量由用户输入，允许 0 表示未完成，不能以未填写自动代入目标值。实际值上限 10000，不能为未来日期或周期外日期提前登记。用户手动标记完成或取消完成。统计分母为截至当天应训练次数，未来训练不计入到期完成率。

Agent 复盘读取保存过的记录与确定性统计，不写入完成量，不自动标记完成。复盘保存在计划中；实际记录更新后清除旧复盘，用户可重新生成。当前按需复盘，不后台自动调用付费 AI；不提供穿戴设备采集或医疗诊断。

## 旅行

行程包含起点、目的地、1–30 天日期范围、全体参与人全程人民币预算、参与人 ID、目的、交通/住宿偏好及额外要求。常见值通过可输入的选项框提供。生成操作先验证输入，再读取选中画像、请求结构化建议，最后校验字段和日期范围，作为未保存草稿供编辑。

每站包含日期、时间、类型、名称、地址、说明及全体参与人费用估算。价格仅为计划估算，不是实时房价/票价；合计超过预算会明确标出，缺少三餐、住宿或某天安排会列出待检查项，用户仍可保存不完整的手动草稿。

AI 不能提供已核实的坐标；前端只从 AI 结果白名单字段构建地点。用户点击检索后，从高德返回的具体匹配项中选择位置。原始 GCJ-02 坐标保存于地点/路线；显示到 OpenStreetMap 时近似转换到 WGS-84，精度仅供行程参考，不替代导航测绘。地图支持拖动和缩放，住宿与其他地点使用不同颜色，悬停显示站点名称与时间。

当天路线按时间顺序逐段查询；仅支持步行或驾车。更改地点名称、地址或其他站点安排后清空旧路线，避免继续显示过期路径；修改名称或地址同时清除该站已匹配的位置。请求全部成功后才提交本次路线结果。取消后忽略迟到结果，也不继续发送下一段请求；已发送的单个请求最多等待后端超时。

保存行程才持久化及加入日历；删除行程需确认。旅程日期在日历上每天展示，点击跳到对应行程及当天；训练事件点击后进入对应周期及训练日。

## 数据与后端边界

业务数据在 `tideplan.life.v1` 中统一保存 `version / people / training / workouts / trips`，使用原有 app_state SQLite 表，不改变现有任务契约。前端验证整份数据后保存，大小上限 2 MiB；损坏数据不自动覆盖，显示恢复提示。现有 JSON 备份原子恢复会包含新数据。保存失败可重试。

AI Key 沿用既有受限权限配置。地图 Key 单独存入本机应用目录 `map-settings.json`，Linux 权限 0600，临时文件写入后原子替换。公开摘要只含配置状态和尾部提示，不包含完整 Key。密钥不存浏览器 localStorage、不发送给 AI、不在备份中。

后端 AI 请求限定为训练生成、周期复盘、旅行生成三个任务，不能执行任意命令。固定 JSON Schema 限制输出结构，前端再次验证范围。沿用已有 `gpt-5.6` 模型；服务商需要支持该模型或其兼容路由及 Responses 的结构化输出。请求超时 120 秒，地图请求超时 20 秒；网络、权限、限额和无结果状态向用户显示。

## 模块与设计

沿用 React / TypeScript / Tauri，新增 Leaflet 按需地图模块。ui-design 技能用于确定“人物档案 → 可执行计划 → 实际记录”的布局层次：浅色内容面、青灰色信息层、现有珊瑚色主按钮。人物档案采用列表与编辑区；训练采用日期条与逐组表单；旅行以条件栏配合日程地图。未使用外部组件灵感素材。

| 模块 | 职责 |
| --- | --- |
| `src/life/model.ts` | 共享实体、派生日期、校验、统计及日历映射 |
| `store.ts` / `App.tsx` | 加载、统一状态、持久化及页面编排 |
| `PeoplePage.tsx` | 档案录入、搜索、归档恢复 |
| `FitnessPage.tsx` | 周期草稿、逐组完成记录、复盘 |
| `TravelPage.tsx` | 行程草稿、费用、地点匹配、路线流程 |
| `agent.ts` | 请求生命周期、取消隔离、AI 输出校验 |
| `maps.ts` / `TripMap.tsx` | 地图调用、坐标转换及可视化 |
| `MapSettings.tsx` | 地图 Key 配置界面 |
| `src-tauri/src/planning.rs` | 受约束的结构化 AI 任务 |
| `src-tauri/src/maps.rs` | 地图密钥存储、地点搜索及路线接口 |

实现参考：[OpenAI 结构化输出](https://developers.openai.com/api/docs/guides/structured-outputs)、[高德地理编码](https://lbs.amap.com/api/webservice/guide/api/georegeo)、[高德地点搜索](https://lbs.amap.com/api/webservice/guide/api/search)、[高德路径规划](https://lbs.amap.com/api/webservice/guide/api/direction)。
