# 0.14.0 Android 内测交付

日期：2026-09-27。阶段一已产出可安装的原生 Android 验证包；阶段二、三已建立路线、构建脚本与本地 CI 定义，尚未实现跨设备同步或进行商店发布。完整路线见 [Android 发布路线](android-release-plan.md)。

## 安装包

- `src-tauri/target/release/bundle/apk/Tideplan_0.14.0_android_arm64_internal.apk`
- Android 9 及以上，ARM64；最低 SDK 28、目标 SDK 36。
- 版本 `0.14.0-internal`，versionCode `1400`，包名 `com.tideplan.mobile.debug`。
- 安装名称「潮汐计划 · 内测」，打开后设置底部显示 0.14.0。
- 大小 41,074,545 字节（约 39.2 MiB）；SHA-256：`6aa828c594a114d5dd64a102e379ffcd0af3d9dba4f1c96ea0b269f04ed49488`。
- 调试签名，开启 WebView 调试，仅供内测。不可作为正式商店发行包。
- 调试包和预留正式包 `com.tideplan.mobile` 数据分离。升级不要卸载；更换签名或迁移包名前先导出备份。恢复会覆盖本机业务数据，服务密钥需另行配置。

构建：`npm run android:doctor`、`npm run android:build`。正式签名构建入口为 `npm run android:release`，必须提供仓库外已有密钥和签名环境变量。没有生成正式密钥、推送代码或触发远程 CI。

## 实现范围

- React / Rust / SQLite 复用；托盘、自启、窗口控制、项目目录扫描按平台隔离。
- 手机「今天 / 助手 / 工具」导航，保留任务、日历、笔记、关键日期、人物、训练、饮食采购与旅行入口。工作观察和拼豆工作台暂留桌面端。
- 系统返回键、状态栏与导航栏避让、软键盘显示区域、窄屏交互。手机对话回车换行，点击发送按钮发送；理解图只读，交付仍需用户执行。
- Android AlarmManager 安排可调早晚提醒，权限由用户主动授权；支持重启、时区变化与更新后重排。通知正文使用通用提示，不暴露个人内容。未申请精确闹钟权限，系统可能延迟。
- AI 与地图凭据由 Android Keystore AES-GCM 加密后落盘；SQLite 本身未加密。AI 功能继续共用服务配置。系统云备份关闭，应用内备份不包含密钥。
- 原生文档选择器用于用户选择备份和导出位置；本地备份用于手动迁移，不是双向同步。
- 新安装的桌面工作观察默认关闭，不携带开发者私人目录；原配置保留。

- TypeScript / Vite 构建成功，前端 67 项测试通过。
- Rust 48 项测试通过，格式检查和 Clippy（警告视为错误）通过。
- Android ARM64 Rust / Gradle 构建成功；原生时间计算 4 项测试通过，涵盖夏令时和次日调度。
- 浏览器 320 / 390 宽度交互检查：手机导航、禁用桌面入口、年份跳转、任务日期与笔记、聊天回车换行、工具页无横向溢出。
- Android 16 模拟器实际安装 ARM64 APK（x86_64 模拟器的 ARM 转译）。本地模拟服务验证：共享 AI 配置 → 连接测试 → 对话 → 理解图 → 执行清单 → 任务 → 日历 → 笔记 → 完成；没有调用真实收费服务。
- 覆盖安装并重新启动后，任务、笔记、完成状态与 AI 配置保留；安全配置文件具有加密封套，重启后连接测试成功。地图配置也已验证加密写入及最终 APK 重启后读取。
- 实际系统文档选择器将 JSON 备份保存到 Downloads，再选回、确认覆盖并重载；恢复前安全副本存在，任务与笔记保留；导出的备份不包含合成测试密钥。取消导出后界面解除忙碌状态，没有产生导出错误。
- 系统通知权限弹窗与测试通知已验证；系统中可见 09:00 / 19:00 两个提醒安排，关闭后取消。未宣称已完成跨日实际送达、Doze、重启与厂商省电测试。
- 原生截图确认状态栏、底部手势区和软键盘不会覆盖输入框；键盘出现时 CSS 视口正确缩小。
- APK 签名验证、ZIP 16 KB 对齐、原生 ELF 16 KB LOAD 对齐检查通过；尚未在 16 KB 页大小设备运行。

脚本：`scripts/mobile-ui-smoke.js`、`scripts/android-native-smoke.js`、`scripts/android-smoke-service.mjs`。原生脚本仅用于隔离测试安装，会创建合成任务和测试配置；不能对用户的日常数据库直接执行。截图位于 `output/playwright/android-native-*.png`。

## 限制与下一阶段

- Pixel 9a 解锁后已补做真机核心流程验收，见下文。早期 `com.tideplan.mobile` 验证包保持不动；本次验证和后续打开应使用「潮汐计划 · 内测」对应的 `.debug` 包。
- 模拟器初期因系统负载出现 SystemUI 和应用 ANR；关闭本轮构建守护进程、降低隔离模拟器后台负载后完成核心流程。不能据此承诺低端真机性能，需纳入性能验收。
- 本轮没有新构建 Linux 安装包；桌面 Rust 检查通过不等于 Linux 安装、托盘和通知回归全部完成。
- 还需验证真实 AI / 地图服务、采购 Markdown 导出、弱网与取消恢复、大字体和无障碍、多厂商 Android 9–16、通知跨日送达和升级失败恢复。采购 CSV 已在 Pixel 真机验证。
- 跨设备同步需要账户、服务部署与地域、稳定 ID / 修订号 / 删除标记、冲突处理、离线队列和数据删除策略；当前没有云端。
- 正式发布还需要确定渠道、发行主体、长期签名归属、隐私政策与支持入口、第三方许可、正式 APK / AAB 和商店材料。既有签名保护脚本与 CI 定义只是准备工作，未完成上架。

模拟器使用本轮创建的隔离 AVD `TideplanReleaseQA_20260927`。关闭后保留合成数据和测试备份便于复核，不纳入发行 APK。

## Pixel 9a 真机补验（2026-09-27）

设备报告 Android 17 / API 37、ARM64、4 KB 内存页。安装的是上文同一 SHA-256 的最终 APK，补验未修改应用代码。

- 安装前确认 `.debug` 包不存在，测试在新建的独立沙箱进行；没有覆盖旧包或使用用户真实 AI 密钥。使用本地模拟服务，不代表真实模型质量验收。
- 共享 AI 配置保存、连接测试、对话、只读理解图、批量执行两项交付、生成一项明确任务、日历显示、记事本保存、完成任务均通过。
- 软键盘显示时输入区域完整留在视口内；系统返回键收起键盘后恢复视口，再次在工具侧栏中按返回键关闭侧栏。
- 点击授权并测试后，系统内出现本应用 `9199` 测试通知；可见 09:00 / 19:00 原生 AlarmManager 调度。没有更改手机时间、重启整台手机或强制进入 Doze，尚未验证跨日实际送达。
- 原生文件选择器导出 JSON 备份，确认其中包含任务且不包含测试密钥。中文输入法会转换自动化输入的字母文件名，因此本次备份采用纯数字测试名 `Download/202609279001.json`。
- 新建「真机测试番茄，2 斤」，通过原生文件选择器导出 `Download/采购清单-2026-09-27.csv`，读取文件验证物品与数量正确。
- 从文件选择器重新选入先前 JSON，确认覆盖恢复并等待重载：已完成任务保留，备份后新增的测试采购项被移除；恢复前安全副本已生成。这是实际文件读取与数据库恢复验证。
- 最终 APK 在真机覆盖安装并冷启动后，任务、笔记、完成状态仍保留；使用已加密落盘的 AI 配置重新通过本地连接测试，确认设备密钥解密链路可用。
- 关闭提醒后，系统中本应用的两个待执行闹钟被取消；随后恢复安装时默认的启用状态与 09:00 / 19:00 时间。
- 收尾已清除合成 AI 密钥，并将 BASE_URL 从测试电脑地址恢复为默认服务地址；没有留下依赖本地测试服务器的配置。使用真实 AI 前请在设置中填写自己的服务地址、模型与密钥。
