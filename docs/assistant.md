# 潮汐助手 · 0.10.0

0.11.0 增加「想法与目标」交接：聊天中的想法可存入独立收集箱，继续形成目标、子目标和整份行动方案，采用后原子并入业务。任务摘要也包含有上限的目标与行动关系。新增工具 `organize_thoughts` 只提出可检查的交接卡，不直接写入目标。具体范围见 [目标推进说明](goal-workflow.md)。下文记录最初 0.10.0 助手基础能力。

## 产品与界面

“小汐”是可改名的潮汐小精灵，从顶栏打开，快捷键 Ctrl + Shift + Space。水滴形象、轻呼吸状态、浅海青/落日杏配色与应用现有玻璃和纸面风格一致。使用现有 React + Vite + Tauri 栈；图形直接用 SVG/CSS 绘制，没有额外图像服务或外部组件模板。

助手以一个跨页面侧栏提供自然语言入口。可以收起后继续查看业务页面，正在进行的请求保持运行；支持停止本轮请求。不会主动弹出对话或主动运行后台任务。

## 第一版能力

- 整理已分享的近期任务、日历安排、餐食/采购和项目扫描统计，给出复盘及下一步建议。
- 根据需求调用 `read_workspace` 获取本轮允许范围内的快照；回复标注实际读取的业务范围。
- 调用 `suggest_page` 给出应用内功能入口，用户点击后跳转。
- 调用 `draft_task` 提出最多六张计划草稿卡，展示标题、期限、跨度、优先级和说明。点击后进入现有计划编辑器，用户检查修改并保存。已有未完成草稿时不会覆盖。
- 自定义名字、配色、交流风格、明确偏好。偏好是可见文本；不自动推断人格、健康情况或长期记忆。

食谱、训练、旅行、拼豆、工作观察等专门工作流继续由原页面处理。助手可以解释、总结和提供入口，当前不在对话中直接执行这些页面的生成/同步操作，也不能删除记录、标记完成、读取文件、执行终端命令或代用户订票。

## AI 接入

共用现有 API_KEY、BASE_URL 和模型名称。API_KEY 只在 Rust 层读取，不进入 UI、上下文和备份。按 [OpenAI 官方 Function calling 文档](https://developers.openai.com/api/docs/guides/function-calling) 实现 Responses API 工具循环：提供闭合 JSON Schema → 模型请求工具 → 本机验证并产生只读结果或待确认草稿 → 带原 `call_id` 回传工具结果 → 模型总结。延续时保留 Responses 所需的输出/推理项，不展示内部推理。

兼容服务须支持 Responses function calling。原来的连接测试只验证 Responses JSON Schema 结构化输出，不代表该服务已经支持助手工具循环。真实模型的质量、权限、限额和兼容性仍取决于配置的服务。

每轮最多四次模型请求、十次工具调用、六张操作卡，总时限 120 秒；单个 HTTP 请求 45 秒，响应上限 1 MB。服务失败、格式错误、步骤超限不提交任何业务更改，输入会恢复。取消会丢弃进行中的本机请求，已到达服务商的请求不能撤回，仍可能收费。

## 数据边界

发送前可选择任务摘要、日历安排、饮食与采购、项目进度，并可查看将提供的快照。默认任务与日历。摘要字段明确列举，排除任务记事本、人物档案（姓名、生日、健康/私人备注）、项目源码和路径。名称本身可能含个人信息，发送前可查看或取消勾选。项目摘要来自最近一次扫描，助手不会自动重新扫描。

对话及名字/风格/明确偏好会发给配置的 AI 服务；已勾选摘要在该轮调用对应读取工具时发送。请求设置 `store:false`，服务商自身的日志与保留策略由服务商决定。取消分享不会撤回过去对话中已经出现的信息，可清空对话重新开始。

本机保存最近 40 条消息、操作卡状态、输入草稿及精灵配置，纳入 SQLite、可靠写入队列和 JSON 备份。每轮最多发送最近 12 条历史消息，并按字节预算进一步裁减。历史卡片的“已打开”只代表用户打开过页面/编辑器，不表示计划已保存。清空对话不会删除精灵偏好、业务计划、已有备份或服务商记录。

第一版没有跨设备同步、多会话列表、自动长期记忆、语音、桌面外常驻宠物或定时自主行动。优先保证统一入口、可理解的数据范围和可检查的操作结果，再根据实际使用增加专业功能的直接委派。
