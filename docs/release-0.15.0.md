# 0.15.0 · Android 提醒检查与采购分享

日期：2026-09-28。Android versionCode 1500，包名保持 `com.tideplan.mobile.debug`，使用原有本机调试签名。本轮接续 Android 阶段二，不改变数据契约，不启动下游工程，不引入账户或云同步。

## 用户入口

- 右上角设置 → 每日计划提醒 → 手机提醒检查：查看应用通知、提醒频道、电池优化、省电模式、系统时区和已安排时间。可以打开通知、频道及电池设置，返回后自动复查；失败时可刷新重试。
- 工具 → 采购清单：先选择全部／手动／AI 食谱及 Markdown／CSV，再点击“分享清单”。系统面板由用户选择接收应用，关闭即可取消；“导出到…”仍支持选择保存位置。
- 手机采购清单的长名称、数量与来源可换行，物品名称 16 px；勾选、编辑、删除采用至少 44 × 44 CSS px 的触控区域。编辑表单和来源筛选适应窄屏，空来源禁用导出与分享。

## 调度与数据边界

以前每次回到前台都取消并重排提醒，可能跳过已到时间但尚未送达的非精确闹钟。本版在配置未变时保留已安排的时段；首次进程启动会重新注册闹钟，以恢复系统强行停止移除的安排，并保留当天待送达时段，不重放更早日期。关闭提醒清除已安排时间和每日通知；通知去重与本地日历／夏令时计算继续生效。

检查页显示调度目标，不表示送达成功。未申请精确闹钟权限，Doze、系统省电及厂商后台限制仍可能延迟。系统设置按钮不自动授予权限或取消电池优化。

分享复用导出的内容生成器，只包含当前筛选的采购数据；每次创建独立缓存快照，UTF-8 文件最大 2 MiB。专用 FileProvider 只暴露采购分享缓存子目录，通过 content URI 临时授予读取权限。下一次分享清理超过 24 小时的旧快照，不清理其他业务数据。打开分享面板不视为已发送到第三方。详见 [数据说明](privacy-and-data.md)。

## 验证

- TypeScript / Vite 与 Android ARM64 APK 构建通过。
- 前端 70 项测试通过，新增覆盖提醒状态引导、共享导出内容和来源筛选。
- Kotlin 单元测试 6 项通过，覆盖本地时间、夏令时、当天延迟提醒的冷启动恢复、旧日期及变化后的时间匹配。
- Playwright 浏览器检查：任务、笔记、日历年份、手机返回逻辑回归；采购增改、空来源禁用、320 / 390 宽度及 844 × 390 横屏无工作区横向溢出；44 px 采购按钮与 320 宽度提醒面板。
- APK 签名验证和 ZIP 16 KB 对齐检查通过；这不等于已在 16 KB 页面设备验证运行。
- Rust `cargo fmt --check`、Linux 目标 `cargo clippy --lib -- -D warnings` 通过，Android Rust 代码随 APK 实际编译通过。
- 隔离 Android 16/API 36.1 模拟器覆盖安装成功。2 项原生 instrumentation 测试通过：分享 URI 的内容、MIME、临时读取标志、多次分享快照独立、拒绝私有目录与非法格式／超量内容；恢复前台保留到点时段及关闭后的调度清理。

- 模拟器实装界面：提醒检查显示真实权限、时区、两个计划时间及省电状态；三个按钮分别进入应用通知设置、频道设置和电池优化页。采购页面新增模拟物品 → CSV → 分享清单，Android Chooser 显示 1 个 CSV 文件和接收应用列表；取消后返回应用，未选择接收者、未对外发送数据。
- 模拟器强行停止后重新冷启动，采购记录仍在；AlarmManager 中重新出现两个本应用的 RTC_WAKEUP 调度，原生状态查询的目标时间与停止前一致。该检查验证重新注册，不代表已经验证跨日送达。
- 设备界面检查曾被模拟器 System UI 的无响应弹窗阻挡。关闭该系统弹窗后完成上述交互。当前主机内存压力较大，不能用本次模拟器耗时作为应用性能结论。

本轮未连接实体手机，不将模拟器测试称为真机验收。自动化定义已加入本地 Android CI 文件，但未触发远程 CI 或发布。

## 安装产物

`src-tauri/target/release/bundle/apk/Tideplan_0.15.0_android_arm64_internal.apk`

大小 41,221,193 字节（约 39.3 MiB），ARM64，最低 Android 9/API 28，targetSdk 36。同目录提供 `.sha256` 校验文件。

SHA-256：`07284119379d74abd175a8f467d4f57e18bababde76a8ef80c06ec2931cbb2fd`。

使用本机之前的内测签名，可以覆盖本机产出的 0.14.x 内测包；不需要卸载旧版。安装后在设置里应看到 0.15.0。仍是含 WebView 调试能力的内测包，不是商店发行包。旧 0.14.1 安装包保留。

原生测试可在隔离安装上复现：构建 `:app:assembleUniversalDebugAndroidTest`、安装主 APK 与 androidTest APK、授予测试安装通知权限，然后运行 `adb -s <QA设备> shell am instrument -w -r com.tideplan.mobile.debug.test/androidx.test.runner.AndroidJUnitRunner`。测试会暂时更改提醒安排，不应对用户正在使用的安装直接运行。
